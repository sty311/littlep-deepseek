# Local source-package security audit

Scope: staged source, documentation, configuration example, patch manifests, tests, workflows and final source archive. Private development trees and the running device were not modified.

Checks use filename/category reporting only; matched credential values are never copied into reports. Rules cover key-like strings, actual private-project key comparison, authorization-value patterns, machine paths, unique device identifiers, MAC-like values, forbidden binary extensions, oversized/non-text files, and archive exclusions. References such as `Authorization` in HTTP code are expected; they are not credentials. The configuration example contains only `YOUR_DEEPSEEK_API_KEY`.

No actual API key, owner workstation path, device serial, account cookie, Wi-Fi credential, firmware image, original/patched vendor binary, user scan, screenshot or captured request/log is included. UI fixtures are generated text and mock components; JPEG fixtures are generated by tests. Native and bytecode recipes contain only narrow transform data, preimage guards and expected digests, not complete vendor files.

Two staged/archive scans and independent-copy checks passed, with zero private-value matches. Build outputs are local, ignored by version control and excluded from the source ZIP. No upload, GitHub operation, device request or live model call is part of verification.

Limits: a pattern scan cannot prove absence of every possible secret or settle copyright ownership. Review new contributions and generated private outputs before any future publication. External compiler redistribution rights are not established; it is deliberately not included. See [NOTICE.md](NOTICE.md) and [SECURITY.md](SECURITY.md).
